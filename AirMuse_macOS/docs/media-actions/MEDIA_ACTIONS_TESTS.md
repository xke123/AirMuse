# 回归与验收协议
使用现有 Swift Testing/XCTest、mock provider、可控时钟、可阻塞 continuation 与确定性随机源；不要依赖 sleep 推断竞态。真实接口验证独立记录。以下为待执行测试，不是已通过结果。

| ID | 场景 | 预期 |
|---|---|---|
| T01 | 六类资源菜单 | 精确匹配 SPEC，未授权动作不出现 |
| T02 | 自建/协作/归属未知歌单 | 无容器写操作，即使 provider 宣称支持 |
| T03 | 个人歌单曲目 | 单曲收藏允许，歌单成员不变 |
| T04 | 当前详情导航 | 同 ID 导航隐藏，不同专辑/合作艺人可跳转 |
| T05 | 仅播放单曲与行点击 | 单曲替换 vs 从所在集合开始 |
| T06 | 五意图 A/B/C/D 与 X/Y/Z | 严格符合 SPEC 表 |
| T07 | 随机完整集合 | 全量参与，确定顺序，不重复抽签 |
| T08 | 随机中明确插入批次 | 批次顺序不被打散 |
| T09 | 队列双击/移动/删除 | 保留其他待播与 UUID，不新增重复条目 |
| T10 | 同曲多来源 | 独立 UUID 和来源，操作精确命中 |
| T11 | 无当前播放时追加 | 不自动播放，主播放消费队首 |

| T13 | 慢 A 快 B 播放请求 | 最新意图 B 胜出 |
| T14 | 批量追加请求乱序 | 确定提交顺序，切换队列后旧结果不提交 |
| T15 | 350+ 曲目分页 | 不截断，失败可见，重试从失败页开始 |

| T20 | 移除订阅歌单 | 不删除自建歌单，归属与 ID 校验 |
| T21 | 取消收藏 | 不假定移除资料库，读回联动 |
| T22 | 收藏自动添加资料库 | 两状态正确同步 |
| T23 | 快速交替收藏/取消 | 最终目标一致，不被旧响应覆盖 |
| T24 | 请求超时但服务端已执行 | 核对状态，不盲目重复写 |
| T25 | 401/403/网络失败 | 权限降级、错误可见、无假成功 |
| T26 | A→B 账户切换途中写入/查询 | 旧状态与回调不污染 B |
| T27 | 资料库删除当前/待播歌曲 | 不主动改变队列或停止音频，必要时目录 ID 解析 |

| T29 | 导航、菜单开关、hover | 无播放/写命令；无逐项网络请求 |
| T30 | 同资源多页面 | 差量状态刷新，保留滚动及选择 |
| T31 | 动画反转与隐藏 | 旧 completion 无副作用、命中/焦点一致 |
| T32 | Original/Enhanced 与辅助设置 | 原皮肤保留，真实玻璃实测、键盘与 VoiceOver |

| T35 | 删除确认与取消 | 取消零写请求，明确资源及影响 |

执行：检查实际 Package.swift 后运行适用 `swift build`、`swift test` 及各模块过滤测试；记录真实命令与退出码。手工验证登录 Apple Music 测试账户的四项写能力、歌曲/专辑/平台歌单/艺人状态及联动；macOS 实机录制菜单、焦点、动画和降级；Instruments 测主线程、内存、WebKit 子进程、空闲时钟及帧时间。性能目标 60/120Hz 帧预算 16.67/8.33ms，菜单本地生成、零逐项请求；实测与基线对照，不虚报通过。

## 基线新增的定向验收（纳入既有编号）
- T06/T07：验证四种意图仍通过现有 submitIntent；随机替换及顺序替换的模式和首曲在一次状态提交中确定；无 UI 两次 await 竞态；已有随机模式不污染明确顺序播放。
- T17/T25：QueueCommandResult 已接受而引擎失败，UI 不显示已经开始播放；已有错误反馈路径可见。
- T23/T25/T26：艺人 setArtistRating 请求失败、超时、快速交替或换账户，header、详情、卡片及菜单均按有效状态同步；旧响应不能覆盖新目标。不得仅写日志。
- T01/T29：旧 makeQueueContextMenu 与新菜单不可同时触发同一指令；菜单构建不发写请求。
