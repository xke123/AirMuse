# Apple Music 真实能力验证与安全门槛

当前源码事实：`AppleMusicProvider.mediaActionCapabilities` 对资料库写入关闭，只允许 artist 收藏；`addToLibrary`/`removeFromLibrary` 直接 unsupported；`fetchResourceState` 只处理 artist，其他 unknown；歌曲电台关闭。`AppleMusicAmpClient.setArtistRating` 已有 PUT/DELETE 实现。此文档不提供猜测的私有端点、不宣称真实接口已经验证。

## 能力验证流程
1. 复核现有授权会话、generation 检查、请求封装、缓存与错误分类。优先复用真实已有方法；核对 Apple 官方公开 API/MusicKit 文档和正常授权网页实际行为。官方 API 支持不等于现有 Web 会话授权，需验证对应认证模式。
2. 如需真实账号联调，由用户在其 macOS 环境通过正常登录提供授权会话。只在用户明确允许的测试账号/测试资源上写入；不得要求粘贴 token/cookie、截取或导出凭证、绕过订阅权限或使用未授权资源。证据只保留脱敏请求方法、资源类型/匿名标识、状态码、响应字段、结果和时间；不保存秘密或私人曲目清单。
3. 先证实可读状态和 ID 映射，再验证安全、可逆写入。对歌曲/专辑/平台歌单分别验证 add、remove、favorite、unfavorite；对艺人验证 favorite/unfavorite 与电台；歌曲电台验证真实资源类型。平台订阅歌单的移除必须证明只解除资料库关系，不删除歌单对象或个人歌单成员。禁止用真实个人歌单尝试破坏性操作。
4. 确认平台联动规则（收藏自动入库、移除是否影响收藏/下载/歌单成员等），按资源及账户设置区分；无法确认不会违背个人歌单只读规则时，关闭危险路径并记录阻塞。不要由本地代码推测服务端副作用。
5. 对照真实读回、跨页面/重启后的状态、失败/超时核对、权限错误和切换账户。确认写操作不主动干扰本地播放。对写后读取禁用过期缓存或采用可证实的新鲜读；若存在 eventual consistency，有限退避、明确处理中/未知，不无限轮询。不得盲目重试具有未知结果的写操作。

## 生产接口要求
沿用 `MediaResourceMutationProvider`，最小扩展 receipt/能力模型以支持字段补丁和结果未知；禁止伪造成功或默认 false。真实请求前重新核查捕获 scope、resource ownership 和 library ID；不以 prefix 推断可删除。`setArtistRating` 接入统一状态机，检查 catalog artist ID 与 library artist ID 映射；写后 `fetchArtistDetail` 失败时不能以目标值当已确认，按接口实际证据确定 pending/unknown。Artist 详情评级字段缺失/请求失败不等价于未收藏。所有真实状态读取可复用已有详情或批量查询，不为每张卡片发送独立请求。
