# PD — 目标与范围

## 核心判断
播放器业务机制已经形成。解耦的目标不是新增平台数量，而是接入第二个平台时无需修改通用前端、队列和播放内核。参考 HEAD `3daa253b227e8905927e2c61e5009099e98c6ac1`，最终以实际源码为准。

| ID | 交付目标 | 可验证结果 |
|---|---|---|
| G01 | 编译边界 | UI、Domain、Playback、Application 不直接或传递依赖具体 Adapter；独立通用宿主构建并启动 |
| G02 | 通用契约 | 资源/账户/地区/游标/错误/能力有明确类型；无平台特有前缀解析和默认身份 |
| G03 | Apple Music 保真封装 | 已有目录、搜索、资料库、收藏、电台、登录、播放及缓存能力迁移，不重写接口或弱化功能 |
| G04 | 通用应用服务 | LibraryWindowController 只处理展示与交互；业务服务统一浏览、集合、操作、导航、账户 |
| G05 | 独立平台生命周期 | 注册、按需激活、浏览独立、账户隔离、关闭与释放，未激活平台无运行时开销 |
| G06 | 单一播放内核与引擎路由 | 同一协调器/队列/Store，安全音频权交接、失败与旧事件隔离 |
| G07 | 来源与队列正确性 | 来源跨浏览平台纯导航，普通/远端能力按证据决定，单平台队列和电台契约无回退 |
| G08 | 可替换性与效率 | Apple Music 与独立 Fixture 通过同一生产链路；视觉及性能不退化，测试、实机证据齐全 |

## 边界
本期采用编译期注册（非动态插件、非第三方扩展加载）；不新增真实 Spotify/QQ/本地文件导入功能。现存未完成适配器隔离保留，不将其宣传为已可用。允许测试专用 Fixture、无真实凭证的独立宿主与测试引擎；不将测试平台暴露给正式用户。单音频活动引擎，单平台/账户队列；不做混合队列、多音频同时播放、后台自动切换或隐藏恢复栈。跨平台普通播放/随机替换允许，跨平台插播/追加/队首/队尾明确拒绝（产品设计默认，后续扩展另议）。浏览切换不要求停止播放。无歌单编辑、分享或新平台授权策略变更。

## 交付门槛
代码路径迁移完成并移除旧生产调用链；不能仅建立协议或在 UI 外套一个仍依赖具体类型的 facade。无 Adapter 构建证明需要使用不链接 Apple Music 的独立 fixture host/target 或等价构建配置，真实生产 App 可以继续注册 Apple Music。测试必须穿越同一 Application/Playback/UI 路径，不能使用另一套模拟播放器。真实 Apple Music 验收、真实音频、原生 UI 和性能测试未执行时不得标 VERIFIED。
