# 播放队列行为规范

## 模式与顺序
顺序：消费 upcoming 首项，耗尽停止。随机：开启时 Fisher–Yates 打乱尚未播放的基础成员，当前与历史不变；本轮不重复消费同一条目（重复歌曲独立 ID）。关闭随机恢复未播放条目的基础相对顺序。明确手动编辑优先：拖拽、移至头尾同时更新待播与基础相对位置，未参与拖拽的成员保持相对顺序；关闭随机不丢失显式编辑。插入下一首保持批次顺序并优先于随机，追加不触发洗牌。可注入随机源。循环 all：本轮耗尽时从有效循环成员生成下一轮，随机开启则重新洗牌，多于一项尽量避免跨轮同条目连续；one：仅自然结束重播当前，手动下一首不受限制。one/all 互斥，shuffle 独立。空循环成员不产生新曲目；单曲循环仍可重播当前。

## 操作
| 操作 | 规则 |
|---|---|
| 播放（替换队列 `replaceAndPlay`） | 按入口语义建立新队列并替换旧计划，捕获来源；明确选中行索引/条目而非 `firstIndex(track.id)` |
| 立即插播（`interruptAndPlay`） | 立即切换播放目标，保留原待播并将选中批次其余曲目置于原待播前；原已确认曲目待新目标确认后进入历史 |
| 下一首播放（`prepend`） | 插入待播头部；同一批次内部顺序不变；后一次显式插入优先 |
| 添加到队列（`append`） | 末尾追加，不重新排序或启动音频 |
| 空闲添加 | 只建立待播；Play 消费首项，Next 同样可开始首项 |
| 双击待播 | 提取该条目并请求播放，其他待播保持相对顺序 |
| 删除/多选删除 | 仅删待播条目及循环成员；当前、实际历史不动 |
| 拖拽/移至头尾 | 按条目 ID 及目标锚点变更；保留批量选择的原有顺序 |
| 清空 | 清空待播与全部循环成员，取消分页批次；保留当前音频、位置、历史及模式设置 |
| 上一首 | 播放超过 3 秒先 Seek 到 0，否则回退实际历史；无历史则回到开头 |
| 下一首 | 消费待播首项；列表循环可生成下一轮；否则停止 |
| Undo | 可选单次短时撤销删除/清空，仅在同一队列/会话且没有冲突时恢复，不启动音频；若无法保证安全明确禁用 |

上一首使用实际历史游标与前进路径：回退后，原当前歌曲成为前进候选（与待播合并时去重条目引用，不删除用户原有其他待播），再次 Next 可回到原歌曲；禁止反复回退造成历史自增。显式再次访问不计为随机自动重复。清空后的显式上一首可以回访历史，但历史不会自动复活已清空的循环成员。

自然结束与跳播：确认开始后才把先前确认条目纳入历史并提交目标消费；准备中的条目从可编辑集合中保留为 reservation，失败则明确允许重试或取消，不能静默丢曲。连续切歌以最新操作为准，取消旧 reservation 按定义恢复未消费条目；用户主动新建队列则不恢复旧计划。清空时已经发出播放命令的 reservation 不等同于普通待播：保留明确的当前目标，不让后续旧回调追加其他曲目。

## 分页
首批可播放，后台有界加载剩余；使用 API 返回 next 游标并校验同源及循环游标，保留真实重复歌曲，不按 TrackID 全局去重。加载批次 ID 与 session/queueID 绑定；清空/替换/账户变化使批次失效。每页幂等提交，保留批次段锚点，后续分页不得越过用户追加尾部的边界或覆盖拖拽；若段已删除则拒绝追加。整批插入/追加可先加载完整集合再一次提交，以保证顺序。完整随机须完整曲目集合，加载中禁用开启全量随机并显示原因；已开启随机时新建大型来源先完成集合后生成顺序，允许取消。分页失败展示部分队列及重试，不伪称完整。

## 远端电台
QueueOwner.localCoordinator 普通歌曲只由本地计划推进，WebEngine 以单曲执行；remoteEngine 不由本地自然结束事件推进。QueueCapabilities 分别描述可读、插入、删除、排序、清空、随机、单曲循环、列表循环及跳过能力；默认未知/禁用，实测后开启。远端仅有当前曲目时显示自动续播而非空本地队列；来源继承当前电台。普通歌曲添加到不支持混合队列的电台时明确提示切换，取消无副作用，不静默停止电台。
