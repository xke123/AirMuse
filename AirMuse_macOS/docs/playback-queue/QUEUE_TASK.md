# AirMuse — Playback Queue Management

## Agent 执行入口
本任务是实际实现完整播放队列控制，而非输出方案。先读取仓库根 AGENTS.md（保留不覆盖）、本目录全部文档与当前源码。审计基准为 main 的 f494b09c35583065f4a9a7fdf7ecb4ca5314a982；若仓库更新，以实际实现为准，记录差异。已有曲目来源模型、导航与玻璃组件直接复用，不重复建设。

目标：用户看到的待播顺序就是下一次正常推进所采用的顺序；所有队列操作共享唯一权威状态，编辑不打断当前音频。完成 Q01–Q20，按 ROADMAP 推进并维护 PROGRESS。不要在计划或空接口阶段停止。每阶段审查 diff、构建、运行相关测试并记录结果。不得覆盖用户未提交的工作，不擅自推送远端。

范围：队列条目身份、顺序、历史、播放模式、编辑、音乐库添加入口、分页、低频状态发布、持久化、账户隔离、动态电台能力、原生玻璃队列面板及回归测试。不重新设计登录、鉴权、网络基础设施、歌词、图片缓存、主播放器皮肤或音乐库整体布局。不新增平台接入、跨设备同步、远端歌单写入或智能续播。

架构约束：现有 PlaybackCoordinatorV2 为唯一队列写入者；QueueManager 是其隔离域内同步值类型，禁止第二个业务 Actor 或 UI 可写副本。WebEngine 执行音频指令，不与本地队列争夺下一首所有权。当前曲目的来源绑定于独立条目，不由当前浏览页面猜测。

验收：真实生产调用链接入，全部可执行测试通过，UI 使用真实快照；不得以假数据、定时模拟播放、空实现、无依据的成功状态代替功能。未能运行的 Apple Music、macOS 原生材质及性能测试明确标为待人工验证，不得标为 VERIFIED。

阅读顺序：QUEUE_BASELINE → QUEUE_ARCHITECTURE → QUEUE_SEMANTICS → QUEUE_UI → QUEUE_ROADMAP → QUEUE_TESTS → QUEUE_PROGRESS。
